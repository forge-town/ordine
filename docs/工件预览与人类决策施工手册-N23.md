> v1 · 2026-06-17 · 适用范围:为 Ordine 补齐"可视化产物 + 人在环决策 + 多文件落库发布"这条能力线,使 design-UI 这类**重可视化、强人类挑选、多文件交付**的 pipeline 能在 Ordine 内跑通,并为"通用、可放心承载他人工作流"打地基。

## 0. 战略结论:原生薄层 + 插件在上(为什么不是纯插件)

这条能力线**不是"加几个算子"**,而是 PRD 自己已经隐含承诺、但还没还的债(目标用户含内容生产/调研分析;最强获客钩子逆向工程要"上传成品样本"——都需要工件预览 + 人类决策)。

分界线是**分层**,不是"插件 vs 原生":

- **能力原语(机制)→ 原生进核心**:工件描述模型、按 contentType 渲染、人类决策节点、发布算子。跨领域通用,且现有插件 API 只能贡献 `objectTypes`([plugin/src/types.ts:41-51](../packages/plugin/src/types.ts#L41-L51)),**根本表达不了**这些;硬塞进单 string `content` 通道会破坏语义边(Ordine 头号差异点)。
- **领域内容(组合)→ 插件/模板**:设计系统的 brief schema、A/B 提示、ui-kit 布局、把它们串起来的参数化 pipeline 模板。

故本期顺序:**先原生长出 4 个原语 + 拓宽插件贡献面(N23-01~N23-10)→ 再把"设计系统 pipeline"做成插件/模板(N23-11)**。插件市场暂缓(契约还没能装下整个领域之前,建商店是反的)。

#### N23-01 · 工件描述 schema(schema-only)
- **改动文件**:新增 `packages/schemas/src/artifact/NodeArtifactSchema.ts`、`ArtifactKindSchema.ts`、`artifact/index.ts`;`packages/schemas/src/index.ts` 加 barrel。
- **做法**:定义轻量工件描述(不动 `NodeCtx` 主通道):
  ```ts
  ArtifactKind = "inline" | "file" | "dir"          // inline=content即内容; file/dir=content是路径
  NodeArtifact = {
    kind: ArtifactKind,
    contentType: TemplateContentType,                // 复用已有 html/markdown/json/text/...
    content?: string,                                 // inline 时为正文; file/dir 时为路径
    files?: { path: string; contentType: TemplateContentType }[],  // dir 时的清单
    label?: string,
  }
  ```
  全部 `z.infer` 派生,枚举走 `${NAME}_ENUM` + `z.enum`。
- **验收**:`bun run check-types`(schemas 包)绿;`bun --filter @repo/schemas test` 加一条 schema 解析单测绿。

- **整体 UI 骨架够用,不需要推倒重做**:`CanvasRoot` 浮层/模态体系([CanvasRoot.tsx:26-47])、`NodeConfig`/`CheckpointDialog` 模态、`runSlice` 运行态、`packages/ui` 原子组件,足以承载新面板的**挂载/状态/容器**。决策 UI 直接沿用 `CheckpointDialog` 的模态外壳。

- **落地顺序建议**:F1 先行(它是 F2/F3 的渲染依赖)→ F3 复用 F1 → F4 最后。

## 4. 特别警告区(违反 = 返工)

1. **不许伪造人类决策**:决策节点禁止"默认自动选第一个/默认勾选";无人选则一直 `waitingForUser`(同 checkpoint)。
2. **不许绕过语义边**:不要把文件集 JSON 偷塞进 `content` 假装单值流过——多文件走 `NodeArtifact{kind:"dir"}` 元数据 + path 捷径,且明确这是过渡态(一等文件集模型记入遗留)。
3. **iframe 必须沙箱**:html 渲染 `sandbox` 且不加 `allow-same-origin`;读产物禁止目录穿越(限定 outputDir 子树)。
4. **发布是对外不可逆**:默认开 PR 不直推默认分支;缺凭证走 waiting + 修复链接,不静默失败。
5. **i18n 双语同步**:任何新 key 必须 en+zh 同时加且被源码引用,否则 `check:i18n` 红。
6. **行数红线 400**:逻辑下沉到 `nodes/`、子组件,别把 Pipeline.ts/大组件继续撑大(即便在 debt 册也不许新增膨胀)。
7. **迁移 ≠ 行为**:Phase D 拓宽插件接口(向后兼容、optional 字段)与"接消费端"分开提交。
