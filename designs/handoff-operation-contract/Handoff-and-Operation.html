File contract proposal · COD-353

Handoff × Operation

让 Operation 明确消费哪些文件、产出哪些文件；让节点之间传递可追踪的文件交接记录，而不是隐式把内容塞进边或 prompt。

现在要改成什么字段代码文件

1. 它现在是什么情况

现有 Operation 已有输入与输出，但它们描述的是对象类型和模板，不是一次运行中真正写出的文件；Pipeline edge 也没有文件产物、端口语义或存储位置。

CURRENT · Operation

可复用操作，输入/输出偏抽象

config.inputs 是 { name, kind, required }，kind 只允许 file | folder | github-project | prompt；config.outputs 是展示/模板项，不承诺真实文件。

CURRENT · Edge

只是节点连接，不是文件交接

PipelineEdge 只有 source / target / sourceHandle / targetHandle。handle 目前可以为 null；无法判断“哪个输出文件”喂给“哪个输入端口”。

2. 我们的方案要改成什么样子

新增“文件型 Operation 契约”。Operation 静态声明输入/输出端口；每次 node run 写出文件后产生 Handoff 元数据；边明确绑定 sourcePortId → targetPortId，并在运行前验证格式兼容。

FileOperation声明可复用的动词、文件端口和 harness。
→
Node run在自己的 run 目录写出真实文件字节。
→
Handoff只传文件元数据、来源与路径，不内嵌文件正文。
→
HandoffEdge绑定 outputPortId 到 inputPortId，先做类型校验。

核心规则

输出文件必须是具体 MIME type（如 application/pdf）；输入端口可以使用模式（如 image/*）。不兼容时必须插入一个可见的转换 Operation，例如 text/markdown → application/pdf，edge 不能暗中转换。

3. 有什么字段

FileOperation

  • id、name、description
  • inputs[]：已声明输入端口
  • outputs[]：已声明输出端口
  • harness：kind、harnessId、allowedTools

Operation 是“动词”。persona / system prompt / 业务 prompt 不放在这里。

输入 / 输出端口

  • 共同：id、label、required、cardinality、description
  • 输入：accepts: MediaTypePattern[]
  • 输出：produces: ConcreteMediaType[]

cardinality 为 one | many。

Handoff

  • handoffId、pipelineRunId
  • producer：node / nodeRun / operation / outputPort
  • sourceFileIds[]：读取过的文件血缘
  • files[]：本次交付的实际文件

文件字节在 node-run 目录，由运行记录 TTL 清理；JSON 只保存引用。

HandoffFile 字段用途
fileId / fileName本次 pipeline run 内的文件身份与可读名称。
relativePath / storageUrinode-run 产物目录内相对路径与实际存储地址。
mediaType具体 MIME type；不能使用通配符。
sizeBytes / sha256?产物大小与可选完整性校验。
HandoffEdge.sourcePortId / targetPortId将图连线绑定到明确的 Operation 输出端口和输入端口。

代码文件

以下是要落到 schema 层的核心文件形状。当前完整评审草案在 docs/spikes/COD-353-file-handoff-contract.ts；它尚未替换生产 OperationSchema。

proposal · operation/FileOperationSchema.ts新增
export const FileOperationSchema = z.object({
  id: z.string().min(1),
  name: z.string().min(1),
  description: z.string().default(""),
  inputs: z.array(OperationInputPortSchema).min(1),
  outputs: z.array(OperationOutputPortSchema).min(1),
  harness: OperationHarnessSchema,
});

export const OperationInputPortSchema = z.object({
  id: z.string().min(1), label: z.string().min(1),
  required: z.boolean().default(true),
  cardinality: z.enum(["one", "many"]).default("one"),
  accepts: z.array(MediaTypePatternSchema).min(1),
});

export const OperationOutputPortSchema = z.object({
  id: z.string().min(1), label: z.string().min(1),
  required: z.boolean().default(true),
  cardinality: z.enum(["one", "many"]).default("one"),
  produces: z.array(ConcreteMediaTypeSchema).min(1),
});
proposal · handoff/HandoffSchema.ts新增
export const HandoffFileSchema = z.object({
  fileId: z.string().min(1),
  fileName: z.string().min(1),
  relativePath: z.string().min(1),
  storageUri: z.string().min(1),
  mediaType: ConcreteMediaTypeSchema,
  sizeBytes: z.number().int().nonnegative(),
  sha256: z.string().regex(/^[a-f0-9]{64}$/i).optional(),
});

export const HandoffSchema = z.object({
  handoffId: z.string().min(1),
  pipelineRunId: z.string().min(1),
  producer: z.object({
    nodeId: z.string().min(1),
    nodeRunId: z.string().min(1),
    operationId: z.string().min(1),
    outputPortId: z.string().min(1),
  }),
  sourceFileIds: z.array(z.string()).default([]),
  files: z.array(HandoffFileSchema).min(1),
});

export const HandoffEdgeSchema = z.object({
  id: z.string().min(1), kind: z.literal("handoff"),
  sourceNodeId: z.string().min(1), sourcePortId: z.string().min(1),
  targetNodeId: z.string().min(1), targetPortId: z.string().min(1),
});
